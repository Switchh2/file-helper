# File Helper

파일을 살펴보고 정리할 항목을 고르는 데 도움을 주는 Windows 앱입니다.

파일이 쌓이면 무엇을 정리해도 되는지 하나씩 확인하기가 번거롭습니다. 파일 정보를 살펴보고 분석할 대상을 고르면, AI가 정리 검토 후보와 이유를 제안합니다. 실제 정리 여부는 사용자가 판단합니다.

## 현재 가능한 것

- ‘파일 선택’ 창에서 파일을 보면서 하나 또는 여러 개 직접 선택
- 폴더를 선택해 바로 안에 있는 파일의 이름·크기·수정일 확인
- 이름순, 큰 파일순, 최근 수정일순 정렬
- 파일 종류 필터: 전체·문서·이미지·동영상/음악·압축파일·설치/실행파일·기타
- 한국어·영어 앱 화면 표시
- 빈 폴더·읽기 실패 안내, 폴더 선택 취소 시 이전 목록 유지
- 파일을 선택해 AI 전달 후보 정보 미리보기: 파일명·확장자·크기·수정일, 최대 20개
- 체크박스로 이번 분석에 포함·제외. 해제한 파일은 목록에 유지
- 전송 미리보기는 파일별 목록으로 표시하고, 정확한 JSON은 펼쳐서 확인
- 확인 후 OpenAI Sol에 메타데이터 전송: 추정 용도·정리 검토 우선순위·확인할 점 표시
- 분석 취소, 마지막 결과 다시 보기 — 다시 보기는 추가 호출 없음

파일은 읽기 전용으로 다룹니다. 하위 폴더 탐색·파일 내용 읽기·이동·삭제·수정은 하지 않습니다. 미리보기의 ‘OpenAI로 전송·분석’을 눌러야 위 메타데이터를 전송합니다. 파일명에도 개인정보가 있을 수 있으니 먼저 확인해주세요. AI 결과는 삭제 안전성을 보장하지 않습니다.

### AI 분석 설정

- 모델 `gpt-6.1-sol`, 추론 `medium`, 출력 상한 4,096토큰, 요청당 최대 20개
- 미리보기 창의 가려진 입력란에 개인 API 키를 입력합니다. 빈칸이면 앱 프로세스의 `OPENAI_API_KEY`를 사용합니다. 패키지 실행에서는 터미널 환경변수가 전달되지 않을 수 있습니다.
- 입력한 키는 해당 요청에만 사용하며 앱에서 파일·설정·로그에 저장하지 않습니다. 공유 저장소나 코드에 키를 넣지 않습니다.
- API 요금이 발생합니다. 자동 재시도는 없으며, 취소·90초 대기 초과도 서버 처리와 과금 취소를 보장하지 않습니다.
- `store: false`로 요청합니다. 이는 API 응답 저장 옵션이며, 서비스의 모든 데이터 보관 정책을 끄는 의미는 아닙니다.
- 결과는 메모리에만 유지하며 폴더를 바꾸거나 앱을 종료하면 사라집니다. AI 우선순위로 목록 자체를 재정렬하는 기능은 아직 없습니다.

## 화면 구성

‘파일 선택’은 파일들이 보이는 창에서 고른 대상만 불러옵니다. 여러 개는 Ctrl/Shift로 선택할 수 있습니다. 불러온 파일은 앱에서 선택된 상태지만, 외부 전송은 별도 미리보기 확인 후에만 진행합니다. 새 선택은 목록에 추가하는 것이 아니라 교체하며, 기존 종류 필터는 ‘전체’로 돌아갑니다. 취소하면 이전 목록·선택·결과를 유지합니다. 20개를 초과해 고르면 목록은 유지하되 AI 분석 전에 선택을 줄이도록 안내합니다.

‘폴더 선택’은 기존처럼 폴더를 고른 뒤 그 안의 파일 목록을 불러오는 기능입니다. Windows 폴더 선택 창 자체에는 파일이 보이지 않으므로 개별 파일을 보고 고를 때는 ‘파일 선택’을 사용합니다.

상단의 제목 아래에서 파일 또는 폴더를 선택합니다. 목록에는 종류 필터·정렬 메뉴·체크박스·이름·크기·수정일을 표시합니다. 아래에서 분석 포함·제외 개수를 확인하고 미리보기를 열 수 있습니다. 미리보기에는 파일별 정보와 접힌 원본 JSON, 키 입력란, 전송 안내가 있습니다. 목록과 미리보기 내용이 길면 스크롤합니다.

배치 기준과 화면 상태는 [기본 화면 설계](docs/ui-design.md)에 정리했습니다.

## 기술 구성

- C#과 .NET 10
- WinUI 3와 Windows App SDK
- XAML 화면 구성
- Resources.resw와 공통 문자열 조회 함수로 한국어·영어 처리

## 실행 방법

Windows 개발 환경에 .NET 10 SDK와 Windows App Development CLI가 필요합니다. `dotnet --version`이 실행되는 터미널에서 프로젝트 루트를 기준으로 실행합니다.

```powershell
& .\scripts\run.ps1 -WinAppPath '<winapp.exe의 실제 경로>'
```

스크립트의 기본 도구 경로는 개발자의 로컬 E 드라이브 경로입니다. 다른 PC에서는 `-WinAppPath`를 지정하고, .NET SDK가 PATH에 포함되도록 준비해야 합니다. 개발자가 별도로 사용하는 환경 설정 스크립트는 이 저장소에 포함되어 있지 않습니다.

```powershell
# 빌드만 확인
& .\scripts\run.ps1 -BuildOnly

# Debug 앱의 영어 화면 확인
& .\scripts\run.ps1 -WinAppPath '<winapp.exe의 실제 경로>' -Language en-US
```

다시 실행하기 전에 이전 앱을 닫습니다. 로그는 `.local/logs`에 저장되며 Git에 포함하지 않습니다. 실행 로그는 빌드·실행 결과이며, 화면 조작 전체를 기록하지는 않습니다.

## 알아둘 제한

- 종류는 마지막 확장자로 분류하며 파일 내용을 검증하지 않습니다. 알려지지 않은 확장자와 확장자 없는 파일은 ‘기타’에 포함됩니다.
- 종류 변경 시 선택과 이전 AI 결과를 초기화합니다. 정렬 변경은 현재 종류 내에서만 적용하고 선택을 유지합니다.
- 필터링된 개수와 전체 개수를 함께 표시합니다. 새 폴더에서도 선택한 종류를 유지하므로 결과가 없다면 ‘전체’를 확인하세요.
- 정렬 변경은 다시 읽기가 아닙니다. 외부에서 파일이 변경됐다면 폴더를 다시 선택해야 합니다.
- 이름순은 문자 기준입니다. `file10`이 `file2`보다 먼저 나올 수 있습니다.
- 크기는 1,024 기준인 KiB·MiB·GiB로 표시합니다. 수정일은 PC의 지역 형식을 따릅니다.
- Windows 폴더 선택 창은 시스템 UI입니다. 앱을 영어로 시험해도 선택 창은 Windows 언어로 표시될 수 있습니다.
- 대규모 폴더 성능 측정과 배포 패키지 검증은 아직 하지 않았습니다.

## 로직 검사

프로젝트 루트에서 .NET 10 SDK로 실행합니다. 별도의 테스트 프레임워크 패키지는 필요하지 않습니다.

```powershell
dotnet run --project tests/FileHelper.Checks/FileHelper.Checks.csproj
```

실제 파일 처리 코드에 테스트용 UI·폴더 선택기를 연결해 목록·정렬·선택·미리보기 JSON을 검사합니다. API 요청과 결과 파싱, 전송 동의·취소 흐름은 모의 HTTP로 검사하며 실제 API 요금은 발생하지 않습니다. 테스트 데이터는 무시되는 `tests/FileHelper.Checks/bin` 아래에 생성합니다. 실제 WinUI 화면 배치와 클릭 동작은 앱 실행으로 별도 확인해야 합니다.
