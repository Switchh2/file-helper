# File Helper 기본 화면 설계

2026년 10월 5일 구현한 폴더 선택·파일 정보 조회·정렬을 바탕으로, 10월 19일 선택 파일 정보 미리보기와 확인 후 AI 분석 흐름을 추가했습니다.

## 화면 배치

상단 원본 선택 카드에는 ‘파일 선택’과 ‘폴더 선택’을 구분해 표시합니다. 파일 선택은 파일이 보이는 시스템 창으로, 하나 또는 여러 파일을 직접 고르는 진입점입니다. 폴더 선택은 해당 폴더의 바로 아래 파일을 모두 나열하는 기존 진입점입니다. 선택 창에서 파일을 고르는 동작은 파일 실행 또는 AI 전송을 뜻하지 않습니다.

직접 선택한 파일은 기존 목록을 교체하고 전체 필터로 전환하며 체크된 상태로 표시합니다. 20개 초과도 누락 없이 표시하지만 분석은 차단합니다. 취소 시 이전 목록을 유지하고, 분석 중에는 두 진입점 모두 비활성화합니다.

| 영역 | 표시 내용 | 배치 이유 |
| --- | --- | --- |
| 상단 | 앱 아이콘, 제목, 짧은 소개 | 앱의 용도를 먼저 알 수 있게 합니다. |
| 원본 선택 카드 | 파일 선택·폴더 선택 버튼, 경로 또는 직접 선택 개수 | 두 선택 방식의 차이와 현재 대상을 보여줍니다. |
| 목록 상단 | 파일 개수, 종류 필터, 정렬 메뉴 | 같은 목록의 범위와 순서를 바꾸므로 목록 가까이에 둡니다. |
| 파일 목록 | 포함 체크박스, 이름, 크기, 수정일 | 분석 대상과 제외 대상을 구분하고 파일 정보를 비교합니다. |
| 목록 하단 | 선택 개수, 미리보기·선택 해제·결과 보기, 분석 상태·취소, 읽기 전용 안내 | 전송 여부와 진행 상태를 확인하고, 결과를 추가 호출 없이 다시 봅니다. |

목록의 열 제목은 스크롤되는 파일 행과 분리했습니다. 긴 이름은 말줄임표로 표시하며, 마우스를 올리면 전체 이름을 보여줍니다.

## 여백과 크기

- 콘텐츠 최대 폭 1,160, 최소 폭 600을 사용합니다. 단위는 XAML의 레이아웃 단위입니다.
- 화면이 넓으면 가운데 배치하고, 좁으면 가로 스크롤로 잘린 영역에 접근할 수 있도록 구성했습니다.
- 바깥 여백은 좌우 32, 위아래 24, 주요 영역 간격은 24입니다.
- 카드 모서리는 12, 내부 여백은 주로 20을 사용합니다.
- 파일 행은 최소 높이 48, 크기 열은 100, 수정일 열은 180입니다.
- 강조색은 파일 선택·미리보기 버튼과 앱 아이콘에 사용합니다. 배경·글자·테두리는 WinUI 테마 리소스를 사용합니다.

이 값들은 현재 초안입니다. 아주 작은 창, 긴 경로, 다른 화면 배율과 다크 모드에서의 시각 검증은 별도로 필요합니다.

## 상태별 표시

| 상태 | 화면 처리 |
| --- | --- |
| 폴더 미선택 | 선택 안내와 빈 목록 안내, 정렬 메뉴 비활성화 |
| 폴더 선택 창 열림 | 중복 선택과 정렬 조작을 잠시 막음 |
| 폴더 파일 읽는 중 | 이전 목록을 비우고 경로와 읽는 중 문구 표시 |
| 직접 고른 파일 불러오기 | 읽기가 완료되면 목록 교체. 취소·불러오기 실패는 기존 목록 유지 |
| 파일 있음 | 파일 개수·각 행 표시, 정렬 활성화 |
| 빈 폴더 | 0개 표시와 빈 목록 안내 |
| 선택 취소 | 기존 경로·목록·정렬 기준 유지 |
| 선택한 폴더 읽기 실패 | 오류 안내, 이전 목록을 다시 표시하지 않음 |
| 개별 파일 정보 조회 실패 | 파일명은 유지하고 크기·수정일은 `—` 표시 |

## 정렬과 표시 기준

- 파일 개수 아래에 파일 종류와 정렬 기준을 나란히 배치합니다.
- 종류는 전체·문서·이미지·동영상/음악·압축파일·설치/실행파일·기타이며 마지막 확장자를 대소문자 구분 없이 비교합니다.
- 알 수 없는 확장자와 확장자 없는 파일은 기타입니다. 파일 내용·안전성 판단과는 무관합니다.
- 필터 변경 시 선택과 마지막 분석 결과를 비웁니다. 숨겨진 파일이 전송되지 않도록 하기 위한 결정입니다.
- ‘표시 개수 / 전체 개수’를 보여주며, 해당 종류가 없는 상태와 실제 빈 폴더를 구분합니다.
- 정렬은 필터 결과에만 적용하며 폴더 변경 시 종류 선택은 유지합니다. 하위 폴더 탐색은 추가하지 않습니다.

- 이름은 대소문자를 구분하지 않는 문자 기준 오름차순입니다.
- 크기는 원본 바이트 수가 큰 파일부터, 수정일은 최근 시각부터 표시합니다.
- 크기·수정일이 같으면 이름순으로 정리하고, 해당 정보를 읽지 못한 파일은 뒤에 둡니다.
- 표시 문자열과 원본 숫자·날짜를 분리합니다. `1.5 MiB` 같은 문자열을 정렬 기준으로 사용하지 않습니다.
- 정렬은 메모리에 보관한 목록만 재배치합니다. 최신 정보를 읽으려면 폴더를 다시 선택합니다.

## 언어 처리

화면의 고정 문구는 한국어·영어 `Resources.resw`에서 가져옵니다. XAML에는 `x:Uid`, C#의 상태 문구에는 `AppText`를 사용합니다. 파일명과 경로는 번역하지 않습니다.

앱 언어 시험 설정은 Windows 전체 언어를 바꾸지 않습니다. 폴더 선택 창의 시스템 문구와 날짜·숫자의 지역 형식은 앱 문구 번역과 구분합니다.

## 이번 화면에 넣지 않은 것

AI 정리 검토 우선순위는 결과 창에 표시하지만 목록 자체의 AI 재정렬은 아직 없습니다. 보관 목록, 삭제·이동, 하위 폴더 탐색도 구현하지 않았습니다. 보관 기능은 핵심 분석 기능의 선행 조건이 아니므로 후순위로 두었습니다.

## 선택 파일 정보 미리보기

1. 체크박스로 분석 포함 여부를 고릅니다. 포함·제외 개수는 목록 아래에 표시합니다. 체크 해제는 파일 삭제나 영구 숨김이 아닙니다.
2. 1개부터 20개까지 선택하면 미리보기를 열 수 있습니다. 20개를 초과하면 일부만 조용히 잘라내지 않고 선택을 줄이도록 안내합니다.
3. 파일명·확장자·크기·수정일을 파일별 목록으로 보여줍니다. 정확한 JSON은 ‘전송 원본 보기’를 펼쳐 확인합니다. 전송 필드는 `name`, `extension`, `sizeBytes`, `modifiedAtLocal` 네 개입니다. 수정일은 로컬 시각이고, 조회하지 못한 값은 `null`입니다.
4. 가려진 키 입력란과 전송 대상·비용 안내를 확인합니다. ‘닫기’는 전송하지 않고, ‘OpenAI로 전송·분석’을 눌러야 요청합니다. 동의 내역은 저장하지 않으며 매 요청 확인합니다.
5. 분석 중에는 폴더·선택·정렬 변경과 중복 요청을 막습니다. ‘분석 취소’는 대기를 중단하며 서버 처리나 요금 취소를 보장하지 않습니다.
6. 결과 창에는 파일명과 추정 용도·정리 검토 우선순위·확인할 점을 표시합니다. 오류는 목록 하단에 남기며, 실패한 응답을 성공 결과로 표시하지 않습니다.
7. 결과는 이번 앱 실행의 메모리에만 보관합니다. ‘분석 결과 보기’는 추가 API 호출 없이 마지막 분석을 보여줍니다. 폴더 변경 또는 새 분석 시작 시 이전 결과를 지웁니다.

파일명에도 개인정보가 포함될 수 있다는 경고를 표시합니다. 전체 경로와 파일 내용은 포함하지 않습니다. 데이터는 마지막 폴더 조회 시점의 메모리 정보이며 미리보기 때문에 디스크를 다시 읽지 않습니다.

정렬을 바꾸거나 폴더 선택을 취소해도 선택은 유지합니다. 새 폴더를 선택하면 이전 선택을 지웁니다. 파일을 읽는 동안에는 선택·미리보기를 비활성화합니다. 앱을 다시 실행하면 선택은 초기화됩니다.

## 확인 결과와 코드 위치

개발자가 목록·정렬 화면을 직접 확인했고, 가운데 정렬 수정 후 화면도 확인했습니다. 자동 검사는 파일 처리 로직 중심이며 픽셀 배치 검사를 대신하지 않습니다.

- [MainPage.xaml](../src/FileHelper/MainPage.xaml): 화면 배치와 행 표시
- [MainPage.xaml.cs](../src/FileHelper/MainPage.xaml.cs): 폴더 선택, 목록 상태와 정렬
- [FileItem.cs](../src/FileHelper/FileItem.cs): 파일 정보와 표시용 속성
- [AppText.cs](../src/FileHelper/AppText.cs): 공통 문자열 조회
- [MainPage.Analysis.cs](../src/FileHelper/MainPage.Analysis.cs): 분석 진행·취소·결과 창
- [FileAnalysisClient.cs](../src/FileHelper/FileAnalysisClient.cs): API 요청과 결과 검증

사용자 실행으로 AI 결과 표시와 개선한 미리보기 화면을 확인했습니다. 자동 검사는 모의 HTTP와 UI 대역을 사용합니다. 긴 파일명, 영어, 작은 창, 여러 배율의 전체 조합 검증은 남아 있습니다.

미리보기 목록 높이는 최대 180, 펼친 JSON은 160, 전체 내용 최대 높이는 480입니다. JSON 영역이 첫 줄만 보였던 문제를 보완하려고 명시적인 높이와 스크롤을 적용했습니다.
