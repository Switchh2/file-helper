# 2026년 10월 5일 개발 기록

오늘은 선택한 폴더의 파일을 조회하고 정렬하는 기본 흐름을 만들었다. 한국어·영어 표시를 붙이고, 마지막에는 오늘 구현한 기능만으로 화면을 정돈했다. AI 분석은 아직 시작하지 않았다.

## 작업 시간

오늘 목표는 7시간이었지만, 실제 순작업 시간 합계는 아직 확정하지 않았다. 대화 중 쉬었다고 기록한 시간은 총 1시간 30분이며, 이후 중단 시간까지 포함한 전체 합계로 단정하지 않는다. 대화가 시작된 시각부터 끝난 시각까지를 전부 개발 시간으로 계산하지 않는다.

## 구현한 내용

- WinUI 앱을 생성하고 빌드·실행을 확인했다.
- 폴더 선택, 경로 표시, 취소 시 기존 목록 유지 기능을 만들었다.
- 선택한 폴더 바로 안의 파일만 읽고, 이름·크기·수정일을 표시했다.
- 이름순, 큰 파일순, 최근 수정일순 선택을 추가했다.
- 고정 문구를 한국어·영어 리소스로 분리하고 공통 조회 함수를 만들었다.
- 실행 결과를 로컬 로그에 남기는 스크립트와 Debug 언어 시험 옵션을 추가했다.
- 폴더 카드와 파일 목록 카드로 화면을 구분하고, 빈 목록 안내와 가운데 정렬을 보완했다.

## 선택한 이유

**조회 범위를 먼저 제한했다.** 하위 폴더까지 탐색하면 시간·권한·오류 처리 범위가 커지므로, 지금은 선택한 폴더의 바로 아래 파일만 다룬다. 파일 내용도 열지 않는다.

**파일 정보와 화면 표시를 나눴다.** `FileItem`에 바이트 수와 수정 시각을 보관하고, 화면에는 읽기 쉬운 크기와 날짜 문자열을 보여준다. 크기순 정렬은 표시된 문자열이 아니라 원본 숫자를 비교한다.

**파일 읽기와 초기 정렬은 UI 스레드 밖에서 처리했다.** `Task.Run`을 사용했다. 다만 로드 후 정렬 메뉴를 바꿀 때의 메모리 정렬은 현재 UI 스레드에서 처리하며, 아주 많은 파일에서의 응답성은 아직 측정하지 않았다.

**번역 문구를 먼저 분리했다.** 앞으로 추가할 화면 문구도 같은 리소스와 공통 함수로 관리할 수 있게 했다. 파일명·경로 자체는 번역하지 않는다.

**보관 기능은 미뤘다.** 초기에는 목록 다음 단계로 생각했지만, 정리 후보를 설명하는 핵심 기능의 선행 조건은 아니라고 판단했다. 다음에는 AI에 보낼 정보와 분석 기준부터 정하기로 했다.

## 막힌 부분과 해결

| 현상 | 확인한 내용과 처리 |
| --- | --- |
| 실행 스크립트가 SDK를 찾지 못함 | SDK 설치 여부와 별개로 새 터미널의 환경 설정이 필요했다. 로컬 환경 설정을 불러온 뒤 실행했다. |
| 영어 시험을 추가한 뒤 앱 시작 실패 | 빌드는 통과했지만 언어 설정 처리에서 예외가 발생했다. 시작 오류 기록을 추가하고, 빈 언어 설정 해제가 가능한 `Windows.Globalization` API로 변경했다. |
| 실행 인자 처리 | 데스크톱 실행 인자는 `Environment.GetCommandLineArgs()`로 읽고, XAML 리소스가 로드되기 전에 적용하도록 했다. |
| 앱은 영어인데 폴더 선택 창은 한국어 | 앱 리소스와 Windows 시스템 UI의 언어 범위가 다른 점을 확인했다. 시스템 창을 별도로 번역하는 작업은 하지 않았다. |
| 전체 화면에서 콘텐츠가 오른쪽으로 치우침 | 스크롤 영역의 가운데 정렬을 명시하고 콘텐츠 폭을 화면 폭에 연결했다. 최대 폭은 유지했으며 수정 후 직접 확인했다. |

SDK 관련 참고: [언어 설정 해제 이슈](https://github.com/microsoft/WindowsAppSDK/issues/5335). 설치된 버전에서 경험한 문제의 기록이며 모든 버전에 동일하다고 단정하지 않는다.

## 검증 결과

### 직접 확인

- 폴더 선택과 취소, 파일 목록 표시
- 크기·수정일 표시 및 정렬 변경
- 한국어·영어 앱 화면과 Windows 폴더 선택 창의 언어 차이
- 카드형 화면 구성과 가운데 정렬 수정 결과

마지막 첨부 화면은 폴더 미선택 상태의 배치를 확인한 자료다. 실제 개인 파일 목록이 포함된 앞선 캡처는 공개 저장소에 넣지 않는다.

### 도구로 확인

- 최종 가운데 정렬 수정본 빌드: 경고 0개, 오류 0개
- 실제 페이지 처리 코드와 실제 임시 파일을 사용한 로직 검사 통과
- 검사 범위: 1,000개 파일·비재귀 조회, 빈 폴더, 목록 교체·취소, 읽기 실패·재시도, 크기 단위, 수정일, 정렬 기준·동률·정보 없음, 빈 상태 표시, 문자열 조회
- 한국어·영어 리소스 키 일치 확인

이 검사는 **화면과 폴더 선택기를 대역으로 바꾼 로컬 검사**다. 실제 WinUI 렌더링, 마우스 조작, Windows의 언어 선택을 자동 검증한 것은 아니다. 검사 프로젝트는 현재 저장소 밖의 개발 환경에 있어, 다른 사람이 저장소만 받아 재실행할 수 있는 테스트 구성은 아직 없다.

컴퓨터 사용 도구로 앱 실행과 UI 항목은 확인했지만 화면 캡처는 시간 초과됐다. 여백·배치의 최종 확인은 개발자의 실행과 첨부 화면을 근거로 한다.

## 아직 확인하지 않은 것

- 대규모 폴더 성능, 네트워크 드라이브·클라우드 파일의 다양한 상태
- 작은 창, 긴 경로, 여러 화면 배율과 다크 모드의 전체 배치
- 배포 패키지와 다른 PC에서의 실행
- AI의 판단 정확도·전송 정보·비용·사용자 동의 흐름

## 다음 작업

1. 파일 정보 중 무엇을 근거로 정리 후보를 추천할지 정한다.
2. AI에 전달할 정보와 사용자 확인 범위를 정한다. 파일 내용은 기본 전송 대상으로 가정하지 않는다.
3. 작은 범위로 분석·설명 표시를 구현한다.

보관 목록은 이후 작업으로 남긴다. 자동 테스트의 저장소 이관과 개발 의존성 버전 고정도 재현 가능한 개발 환경을 위해 후속 검토한다.

## 작업 방식

AI 도움으로 코드를 작성하고, 각 단계의 코드 역할과 선택 이유를 설명받으며 실행 결과를 직접 확인했다. 이번 기록을 혼자 전부 작성·검증한 결과로 표현하지 않는다. 아직 직접 설명하기 어려운 부분은 다음 작업 전에 다시 확인한다.
