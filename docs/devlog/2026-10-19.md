# 2026-10-19 — 파일 선택과 AI 분석 연결

## 오늘 정리

파일 목록을 확인하는 단계에서, 원하는 파일을 골라 전송 정보를 확인한 뒤 AI의 설명을 받아보는 단계까지 연결했다. 구현 중 직접 화면을 보면서 파일 선택 방식, 체크 표시, 미리보기 높이를 보완했다.

작업 시간은 정확하게 측정하지 않아 적지 않는다. 이전 기록의 날짜를 바꾸거나 쉬었던 기간을 작업한 것으로 기록하지 않았다.

## 구현한 흐름

1. **파일 또는 폴더 선택** — 파일 하나/여러 개를 직접 고르거나, 폴더 바로 아래의 파일을 불러온다.
2. **종류·정렬로 대상 좁히기** — 문서, 이미지, 동영상·음악, 압축파일, 설치·실행파일, 기타로 분류한다. 이름·크기·수정일 정렬도 함께 쓴다.
3. **체크박스로 포함·제외** — 체크 해제한 파일은 목록에는 남지만 이번 분석에서 제외한다.
4. **전송 전 확인** — 파일명·확장자·크기·수정일을 읽기 쉬운 목록으로 보여준다. 실제 전송 JSON은 펼쳐서 확인할 수 있다.
5. **명시적으로 전송** — 전송 버튼을 눌러야 OpenAI를 호출한다. 창을 닫거나 파일을 고르는 동작만으로는 전송하지 않는다.
6. **파일별 결과 확인** — 추정 용도, 정리 검토 우선순위, 직접 확인할 점을 표시한다. 결과 다시 보기는 추가 API 호출 없이 가능하다.

한국어·영어 문구를 함께 추가했다. 실제 파일 내용 읽기, 이동, 삭제, 실행은 하지 않는다.

## 구현 중 바뀐 점과 이유

### 1. 먼저 전송할 정보부터 확인했다

처음에는 외부 호출 없이 로컬 JSON 미리보기만 만들었다. 전송 항목을 파일명·확장자·바이트 크기·수정일 네 가지로 제한했다. 파일 객체 전체를 직렬화하지 않아, 나중에 속성이 늘어도 경로나 다른 정보가 따라가지 않게 했다.

조회하지 못한 값은 null이고, 수정일은 로컬 시각이다. 파일명 자체에도 개인정보가 들어갈 수 있다는 안내를 넣었다.

### 2. API 연결과 파일 분석을 구분했다

별도 PowerShell에서 가상 파일 두 개로 연결을 먼저 확인했다. Sol low 요청이 completed로 끝났으며 입력 105·출력 79토큰이었다. 이후 앱에 Sol medium 분석을 연결했고, 앱에서 결과가 표시되는 것을 직접 확인했다.

이 사실은 분석 정확도나 다양한 파일 종류의 유용성을 검증했다는 뜻은 아니다.

### 3. 파일 종류 필터만으로는 선택 과정의 불편을 해결하지 못했다

폴더 선택 창에는 파일이 보이지 않아, 파일이 없는 것처럼 느껴졌다. 앱 목록에 필터를 추가하는 것과 개별 파일을 직접 고르는 것은 다른 요구였다. 파일이 보이는 별도 파일 선택 창을 추가하고 기존 폴더 선택도 유지했다.

직접 고른 파일은 목록을 교체하고 체크된 상태로 보여준다. 기존 필터 때문에 고른 파일이 숨지 않도록 전체로 돌아간다. 취소하면 이전 목록을 유지한다.

### 4. 희미한 선택 표시를 명확한 체크박스로 바꿨다

기존 목록의 선택 표시만으로는 분석 포함 여부를 파악하기 어려웠다. 파일명 앞에 CheckBox를 두고 포함·제외 개수를 표시했다.

정렬은 선택을 유지하지만 종류 필터 변경은 선택과 이전 결과를 초기화한다. 숨겨진 파일이 실수로 전송되지 않게 하기 위해서다. 이는 영구 보관이나 제외 목록 기능이 아니라 이번 분석 대상 선택이다.

### 5. JSON 첫 줄만 보이는 미리보기를 고쳤다

미리보기 영역이 한 줄 높이로 줄어들어 배열 시작 기호인 `[`만 보였다. 기본 표시를 파일별 목록으로 바꾸고, JSON은 접힌 원본 보기로 분리했다. 목록·원본 영역의 높이를 지정하고 전체 내용에 스크롤을 적용했다. 변경 후 화면을 확인하고 현재 단계는 괜찮다고 판단했다.

### 6. 새 터미널에서 SDK를 찾지 못했다

앱 실행 시 `dotnet --version`이 실패했다. 기존 SDK가 없는 문제가 아니라 새 터미널에 로컬 SDK 경로 설정이 적용되지 않은 상태였다. 기존 개발 환경 설정 스크립트를 먼저 불러온 뒤 실행하도록 안내했다. 실행 스크립트의 자동 환경 설정은 이번에 수정하지 않았다.

## API 요청과 안전 범위

- 모델: `gpt-6.1-sol`, 추론: `medium`, 출력 상한: 4,096토큰
- 한 번에 최대 20개. 초과 선택을 임의로 잘라서 보내지 않는다.
- 전송: 파일명, 확장자, 바이트 크기, 수정일. 전체 경로와 내용은 제외한다.
- 개인 API 키: 가려진 입력란 또는 앱 프로세스 환경변수. 앱에서 키·요청·결과를 파일이나 로그에 저장하지 않는다.
- `store: false`: API 응답 저장 옵션이며 모든 서비스 보관 정책을 끄는 의미는 아니다.
- 구조화 응답을 사용하고, 입력 배열 인덱스로 결과를 연결한다. 누락·중복·잘못된 인덱스·미완료·거절 응답을 성공 결과로 표시하지 않는다.
- 파일명은 지시가 아닌 데이터로 취급한다. 모델이 파일 내용·사용 여부를 확인했다고 주장하거나 삭제 안전성을 단정하지 않도록 지시한다.
- 자동 재시도 없음. 취소와 90초 대기 초과는 서버 처리·과금 취소를 보장하지 않는다.
- 결과는 메모리에만 보관한다. 폴더·종류 변경 또는 새 분석 시작 시 이전 결과를 지운다.

## 확인한 것과 남은 검증

| 구분 | 확인 범위 | 확인하지 않은 범위 |
| --- | --- | --- |
| 빌드 | Debug / x64, 오류 0·경고 0 | 배포 패키지와 다른 PC 설치 |
| 자동 검사 | 최종 168개 통과. 실제 로직에 모의 UI·선택기·HTTP를 연결 | 실제 Windows 창 렌더링과 서버 품질 |
| 별도 API 연결 | 가상 파일 2개, completed 응답 | 앱 화면 전체 흐름 |
| 앱 직접 확인 | AI 결과 표시, 미리보기 개선 후 화면 확인 | 모든 파일 종류·오류 상황·언어·화면 배율 조합 |

자동 검사는 실제 API를 호출하지 않는다. 테스트용 가상 파일만 사용하며, 개인 파일 목록·API 키·사용자 화면 캡처는 저장소에 올리지 않는다.

검사 내용에는 목록·정렬·메타데이터, 필터, 체크 상태, 선택 취소, 전송 범위, 중복 호출 방지, 인증·사용 제한·시간 초과·취소·거절·응답 누락, 결과 다시 보기, 미리보기 구성이 포함된다.

```powershell
dotnet run --project tests/FileHelper.Checks/FileHelper.Checks.csproj
```
